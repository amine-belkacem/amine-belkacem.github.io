The detector that listened to the silence

20 November 20264 min readProject: audio-deepfake-generalization

My best deepfake detector reached 1.21 % equal error rate (EER) on ASVspoof 2019. That number looked too good, so I tried to break it. A model that never hears a single word got 19.6 %.

The suspicious number

I trained detectors on ASVspoof 2019 LA, a standard benchmark of real and synthetic speech. A linear probe on layer 3 of a frozen wav2vec 2.0 model reached 1.21 % EER on the evaluation set. But the features are pooled over the whole recording, silence included, and this dataset is known to leak the label through the silence at the start and end of each file.

A detector that only measures silence

So I built the dumbest possible detector: a logistic regression on two numbers, the length of the leading and trailing silence. It never hears the voice.

  • It reaches 19.6 % EER on the evaluation set.
  • The median leading silence is 0.74 s for real voices and 0.04 s for spoofs.

That is not a voice detector. It is a recording-pipeline detector, and it works far too well.

Removing the silence

I trimmed the silence and retrained every system the same way:

Systemeval, as iseval, silence removed
LFCC + GMM10.48 %21.28 %
LFCC + LCNN4.86 %17.40 %
wav2vec 2.0 + probe1.21 %7.68 %

Every system was using the silence, wav2vec 2.0 included. About 8 % is a more honest benchmark figure for it than 1.2 %. On In-the-Wild, a set of real deepfakes of public figures collected online, which has no such leak, the score barely moves (22.44 % → 22.71 %). That confirms the diagnosis.

One more surprise

Filtering out frequency bands showed that the wav2vec 2.0 detector relies almost only on 0–1 kHz: removing that band multiplies its EER by 7 to 9, while removing any band above 2 kHz changes nothing. Is it the voice, or background noise in that band? I have not answered that yet, and I say so in the repository.

Takeaway. A low error rate on a benchmark tells you the model separates the two classes of that dataset, not how. Before trusting a score, build the shortcut detector on purpose, and test on data collected another way.

Le détecteur qui écoutait le silence

20 novembre 20264 min de lectureProjet : audio-deepfake-generalization

Mon meilleur détecteur de deepfakes atteignait 1,21 % de taux d'égale erreur (EER) sur ASVspoof 2019. Le chiffre semblait trop beau, alors j'ai essayé de le casser. Un modèle qui n'entend pas un seul mot a obtenu 19,6 %.

Le chiffre suspect

J'ai entraîné des détecteurs sur ASVspoof 2019 LA, un benchmark classique de voix réelles et synthétiques. Une sonde linéaire sur la couche 3 d'un wav2vec 2.0 figé atteignait 1,21 % d'EER sur l'ensemble d'évaluation. Mais les descripteurs sont moyennés sur tout l'enregistrement, silences compris, et ce jeu de données est connu pour trahir l'étiquette par le silence au début et à la fin des fichiers.

Un détecteur qui ne mesure que le silence

J'ai donc construit le détecteur le plus bête possible : une régression logistique sur deux nombres, la durée du silence au début et à la fin. Il n'entend jamais la voix.

  • Il atteint 19,6 % d'EER sur l'évaluation.
  • Le silence de début médian est de 0,74 s pour les vraies voix et 0,04 s pour les fausses.

Ce n'est pas un détecteur de voix. C'est un détecteur de chaîne d'enregistrement, et il marche beaucoup trop bien.

En retirant le silence

J'ai coupé les silences et réentraîné chaque système de la même façon :

Systèmeéval, tel queléval, sans silence
LFCC + GMM10,48 %21,28 %
LFCC + LCNN4,86 %17,40 %
wav2vec 2.0 + sonde1,21 %7,68 %

Tous les systèmes utilisaient le silence, wav2vec 2.0 compris. Environ 8 % est un chiffre plus honnête que 1,2 %. Sur In-the-Wild, un ensemble de vrais deepfakes de personnalités trouvés en ligne, sans ce biais, le score bouge à peine (22,44 % → 22,71 %). Ça confirme le diagnostic.

Encore une surprise

En filtrant des bandes de fréquence, on voit que le détecteur wav2vec 2.0 s'appuie presque uniquement sur 0–1 kHz : retirer cette bande multiplie son EER par 7 à 9, alors que retirer n'importe quelle bande au-dessus de 2 kHz ne change rien. La voix, ou le bruit de fond dans cette bande ? Je n'ai pas encore la réponse, et je le dis dans le dépôt.

À retenir. Un faible taux d'erreur sur un benchmark montre que le modèle sépare les deux classes de ce jeu de données, pas comment il le fait. Avant de croire un score, construisez exprès le détecteur « raccourci », et testez sur des données collectées autrement.
